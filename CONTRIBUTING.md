# Contributing

Thanks for helping make Forgejo previews better.

- **New format?** Read [docs/ADDING-HANDLERS.md](docs/ADDING-HANDLERS.md) — the handler contract is short and strict (stdin→HTML, always exit 0, dash-compatible, guards for size/timeout/deps). [docs/ROADMAP.md](docs/ROADMAP.md) lists formats we'd love to see.
- **Run the tests**: `sh tests/run.sh` (plain sh, no framework). New handlers need tests: valid, oversized, corrupt, missing-dependency. Fixtures are generated by `tests/fixtures/generate.sh` and committed — keep each under ~100 KB.
- **Shell style**: POSIX sh only; `dash -n` must pass on every script. No dependencies beyond POSIX sh + coreutils in the dispatcher/handlers (conversion tools declared per-handler).
- **Viewer changes**: edit `viewer/src/viewer.js`, rebuild with `sh viewer/build.sh`, and commit the rebuilt `lib/viewer.js` alongside the source change. Dependencies are pinned; adding a new client-side dependency needs discussion in an issue first.
- **Config/sanitizer changes**: `lib/config.sh` is the single source of truth for `app.ini` snippets. If a handler emits new elements/attributes, extend the sanitizer rules in the same PR.
- Keep commits focused with clear messages; open an issue first for anything architectural.
